1. Spring Security

The application uses a stateless JWT-based security model. No server-side session is maintained; every request is authenticated by validating a JWT token extracted from either an HTTP-only cookie or the Authorization: Bearer header.

1.1 Security Filter Chain (WebSecurityConfig.java)

Annotated with @Configuration and @EnableWebSecurity, this class defines the central security policy.

@Configuration
@EnableWebSecurity
public class WebSecurityConfig {

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        http
            .csrf(csrf -> csrf.disable())
            .exceptionHandling(ex -> ex.authenticationEntryPoint(authEntryPointJwt))
            .sessionManagement(sm -> sm.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/auth/**").permitAll()
                .requestMatchers("/v3/api-docs/**", "/swagger-ui/**").permitAll()
                .requestMatchers("/images/**").permitAll()
                .anyRequest().authenticated()
            );

        http.authenticationProvider(authenticationProvider());
        http.addFilterBefore(authTokenFilter(), UsernamePasswordAuthenticationFilter.class);
        return http.build();
    }
}

Key configuration decisions:

SettingValueReason
CSRFDisabledREST API with stateless JWT — no browser session to protect
Session PolicySTATELESSJWT tokens replace server-side sessions
Password EncoderBCryptPasswordEncoderAdaptive hashing, resistant to brute-force
Frame OptionsSAME_ORIGINAllows H2 console access in development

    return true;
} catch (MalformedJwtException e)    { /* invalid token format */ }
  catch (ExpiredJwtException e)      { /* token has expired    */ }
  catch (UnsupportedJwtException e)  { /* unsupported token    */ }
  catch (IllegalArgumentException e) { /* empty claims string  */ }

1.3 JWT Authentication Filter (AuthTokenFilter.java)

Extends OncePerRequestFilter — runs exactly once per request before the rest of the filter chain. Priority: cookies are checked first; the Authorization header is the fallback.

@Override
protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response,
                                FilterChain filterChain) throws ServletException, IOException {
    String jwt = jwtUtils.getJwtFromCookies(request);
    if (jwt == null) jwt = jwtUtils.getJwtFromHeader(request);

    if (jwt != null && jwtUtils.validateJwtToken(jwt)) {
        String username = jwtUtils.getUsernameFromToken(jwt);
        UserDetails userDetails = userDetailsService.loadUserByUsername(username);
        UsernamePasswordAuthenticationToken auth =
            new UsernamePasswordAuthenticationToken(userDetails, null, userDetails.getAuthorities());
        SecurityContextHolder.getContext().setAuthentication(auth);
    }
    filterChain.doFilter(request, response);
}

1.4 Authentication Entry Point (AuthEntryPointJwt.java)

Implements AuthenticationEntryPoint. Called automatically by Spring Security when an unauthenticated request hits a protected endpoint. Returns a structured JSON 401 error instead of a redirect.

{
  "status": 401,
  "error": "Unauthorized",
  "message": "Full authentication is required to access this resource",
  "path": "/api/addresses"
}

1.5 User Details (UserDetailsImpl + UserDetailsServiceImpl)

UserDetailsImpl wraps the User entity to satisfy the Spring Security UserDetails contract. The static factory method build(User user) maps AppRole enum values to SimpleGrantedAuthority instances.

public static UserDetailsImpl build(User user) {
    List<GrantedAuthority> authorities = user.getRoles().stream()
        .map(role -> new SimpleGrantedAuthority(role.getRoleName().name()))
        .collect(Collectors.toList());
    return new UserDetailsImpl(user.getUserId(), user.getUserName(),
                               user.getEmail(), user.getPassword(), authorities);
}

UserDetailsServiceImpl (annotated @Service) implements loadUserByUsername and fetches the User from UserRepository, throwing UsernameNotFoundException if absent.

2. Spring Boot Architecture

The application follows a classic layered (N-tier) architecture. Each layer has a single responsibility and communicates only with the layer directly beneath it.

┌──────────────────────────────────────────────────┐
│                  HTTP Client                      │
└──────────────────────┬───────────────────────────┘
                       │  JSON over HTTP
┌──────────────────────▼───────────────────────────┐
│           Controller Layer (@RestController)      │
│  Handles HTTP routing, input validation,          │
│  maps DTOs to/from service calls                  │
├──────────────────────────────────────────────────┤
│           Service Layer (@Service)                │
│  Encapsulates all business logic, transaction     │
│  management, ModelMapper conversions              │
├──────────────────────────────────────────────────┤
│         Repository Layer (JpaRepository)          │
│  Spring Data JPA — auto-implements CRUD +         │
│  custom JPQL/native queries                       │
├──────────────────────────────────────────────────┤
│           Entity / Model Layer (@Entity)          │
│  JPA-managed POJOs mapped to MySQL tables         │
│  Define relationships, constraints, cascades      │
├──────────────────────────────────────────────────┤
│           MySQL Database (Hibernate ORM)          │
└──────────────────────────────────────────────────┘

Cross-cutting concerns
  ├── Spring Security (authentication + authorization)
  ├── Global Exception Handler (@RestControllerAdvice)
  ├── ModelMapper (entity ↔ DTO translation)
  └── Swagger / OpenAPI (live API documentation)

4. Exception Handling in Spring Boot

All exceptions are handled centrally in MyGlobalExceptionHandler, annotated with @RestControllerAdvice. This class intercepts exceptions thrown anywhere in the controller or service layers and returns a structured JSON error response — no stack traces leak to the client.

Custom Exception Classes

ResourceNotFoundException

public class ResourceNotFoundException extends RuntimeException {
    String resourceName;
    String field;
    String fieldName;
    Long fieldId;

    public ResourceNotFoundException(String resourceName, String field, Long fieldId) {
        super(String.format("%s not found with %s : %d", resourceName, field, fieldId));
        // ...
    }
}

Thrown when a database lookup by ID or name returns no result. For example: category not found, product not found, address not found.

APIException

public class APIException extends RuntimeException {
    public APIException(String message) { super(message); }
}

Used for business-rule violations: duplicate category name, product not in cart, empty cart on checkout, etc.

Global Exception Handler

@RestControllerAdvice
public class MyGlobalExceptionHandler {

    // Validation failures (@Valid on request body fields)
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<Map<String, String>> myMethodArgumentNotValidException(
            MethodArgumentNotValidException e) {
        Map<String, String> response = new HashMap<>();
        e.getBindingResult().getAllErrors().forEach(err -> {
            String fieldName = ((FieldError) err).getField();
            String message   = err.getDefaultMessage();
            response.put(fieldName, message);
        });
        return new ResponseEntity<>(response, HttpStatus.BAD_REQUEST);
    }

    // Entity not found
    @ExceptionHandler(ResourceNotFoundException.class)
    public ResponseEntity<APIResponse> myResourceNotFoundException(ResourceNotFoundException e) {
        return new ResponseEntity<>(new APIResponse(e.getMessage(), false), HttpStatus.NOT_FOUND);
    }

    // Business rule violations
    @ExceptionHandler(APIException.class)
    public ResponseEntity<APIResponse> myAPIException(APIException e) {
        return new ResponseEntity<>(new APIResponse(e.getMessage(), false), HttpStatus.BAD_REQUEST);
    }
}

User

@Entity
@Table(name = "users",
    uniqueConstraints = {
        @UniqueConstraint(columnNames = "username"),
        @UniqueConstraint(columnNames = "email")
    })
public class User {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long userId;

    @NotBlank @Size(max = 20)
    @Column(name = "username")
    private String userName;

    @NotBlank @Size(max = 50) @Email
    private String email;

    @NotBlank @Size(max = 120)
    private String password;

    @ManyToMany(cascade = {CascadeType.PERSIST, CascadeType.MERGE}, fetch = FetchType.EAGER)
    @JoinTable(name = "user_role",
        joinColumns        = @JoinColumn(name = "user_id"),
        inverseJoinColumns = @JoinColumn(name = "role_id"))
    private Set<Role> roles = new HashSet<>();

    @OneToMany(mappedBy = "user", cascade = {CascadeType.PERSIST, CascadeType.MERGE},
               orphanRemoval = true)
    private List<Address> addresses = new ArrayList<>();

    @OneToMany(mappedBy = "user", cascade = {CascadeType.PERSIST, CascadeType.MERGE},
               orphanRemoval = true)
    private Set<Product> products = new HashSet<>();

    @OneToOne(mappedBy = "user", cascade = {CascadeType.PERSIST, CascadeType.MERGE},
              orphanRemoval = true)
    private Cart cart;
}

6. Repositories

All repositories extend JpaRepository<Entity, ID>, which automatically provides: save, findById, findAll, deleteById, count, and existsById. Custom query methods are added only where the derived query syntax or JPQL is needed.

UserRepository

public interface UserRepository extends JpaRepository<User, Long> {
    Optional<User> findByUserName(String userName);   // login lookup
    boolean existsByUserName(String userName);         // duplicate-check on signup
    boolean existsByEmail(String email);              // duplicate-check on signup
}

RoleRepository

public interface RoleRepository extends JpaRepository<Role, Integer> {
    Optional<Role> findByRoleName(AppRole appRole);   // role seed lookup
}

CategoryRepository

public interface CategoryRepository extends JpaRepository<Category, Long> {
    Category findByCategoryName(String categoryName); // duplicate-name guard
}

ProductRepository

public interface ProductRepository extends JpaRepository<Product, Long> {
    // Products in a category sorted cheapest-first
    Page<Product> findByCategoryOrderByPriceAsc(Category category, Pageable pageDetails);

    // Case-insensitive keyword search (SQL LIKE %keyword%)
    Page<Product> findByProductNameLikeIgnoreCase(String keyword, Pageable pageDetails);
}

CartRepository

public interface CartRepository extends JpaRepository<Cart, Long> {

    // Find the cart owned by an email address
    @Query("SELECT c FROM Cart c WHERE c.user.email = ?1")
    Cart findCartByEmail(String email);

    // Used during checkout to verify ownership
    @Query("SELECT c FROM Cart c WHERE c.user.email = ?1 AND c.cartId = ?2")
    Cart findCartByEmailAndCartId(String email, Long cartId);

    // Eager-load carts that contain a specific product (used before product deletion)
    @Query("SELECT c FROM Cart c JOIN FETCH c.cartItems ci " +
           "JOIN FETCH ci.product p WHERE p.productId = ?1")
    List<Cart> findCartsByProductId(Long productId);
}

CartItemRepository

public interface CartItemRepository extends JpaRepository<CartItem, Long> {

    // Find a specific item in a specific cart
    @Query("SELECT ci FROM CartItem ci " +
           "WHERE ci.cart.cartId = ?1 AND ci.product.productId = ?2")
    CartItem findCartItemByProductIdAndCartId(Long cartId, Long productId);

    // Bulk delete (used when removing a product from a cart)
    @Modifying
    @Query("DELETE FROM CartItem ci " +
           "WHERE ci.product.productId = ?1 AND ci.cart.cartId = ?2")
    void deleteCartItemByProductIdAndCartId(Long productId, Long cartId);
}

@Modifying is required on any JPQL DML statement (UPDATE / DELETE) so Hibernate flushes the persistence context and executes the statement immediately.

7. Payload Structure & ModelMapper

DTOs (Data Transfer Objects) live in com.ecommerce.project.payload. They decouple the API contract from the database schema — entities are never serialized directly to JSON.

ModelMapper Configuration

// AppConfig.java
@Configuration
public class AppConfig {

    public ModelMapper modelMapper() {
        return new ModelMapper();
    }
}

// Usage in a service
CategoryDTO categoryDTO = modelMapper.map(category, CategoryDTO.class);
Category category       = modelMapper.map(categoryDTO, Category.class);

ModelMapper uses reflection to copy fields with matching names. When field names diverge between entity and DTO, explicit property mapping or a custom converter is used.

9. Service Layer Logic

Each feature area has an interface and an @Service-annotated implementation class. Services own all business logic, validation, and ModelMapper conversions; controllers are kept thin.

CategoryServiceImpl

MethodLogic
getAllCategoriesBuilds PageRequest from parameters, queries repository, maps to CategoryResponse. Throws APIException if no categories exist.
createCategoryChecks for duplicate name via findByCategoryName; throws APIException if found. Saves and returns DTO.
updateCategoryLooks up existing category; throws ResourceNotFoundException if absent. Updates fields, saves, returns DTO.
deleteCategoryLooks up category; throws ResourceNotFoundException if absent. Deletes (cascades to products via CascadeType.ALL).

ProductServiceImpl

MethodLogic
addProductFinds category; computes specialPrice = price - (discount * 0.01 * price); saves product linked to category and the logged-in seller.
getAllProductsPaginated, sorted query on all products. Returns ProductResponse.

searchProductByKeywordWraps keyword as %keyword% and calls findByProductNameLikeIgnoreCase.
updateProductFinds product; recalculates specialPrice; saves. Then calls updateProductInCarts for every cart containing this product so cart item prices stay current.
deleteProductFinds all carts containing the product via CartRepository.findCartsByProductId; removes the cart item from each; then deletes the product.
updateProductImageDelegates file storage to FileServiceImpl; updates the product's image field with the returned filename.

MethodLogic
addProductToCartRetrieves or creates the user's cart (createCart() private helper). Validates: product exists, quantity ≤ stock, product not already in cart. Creates CartItem, updates totalPrice.

OrderServiceImpl

The most complex service — placing an order is a multi-step transactional operation.

Step 1 — Find user's cart; throw APIException if empty.
Step 2 — Validate the shipping address exists.
Step 3 — Create a Payment entity with the payment gateway details.
Step 4 — Create an Order entity: email, date, address, payment, status = "Order Accepted!"
Step 5 — For each CartItem: validate stock, create an OrderItem, decrement product quantity, save.
Step 6 — Clear the cart: delete all cart items, reset totalPrice to 0.
Step 7 — Map Order to OrderDTO and return.

The entire method is annotated @Transactional so any failure rolls back all database writes atomically.

FileServiceImpl

public String uploadImage(String path, MultipartFile file) throws IOException {
    String originalFileName = file.getOriginalFilename();
    String randomId         = UUID.randomUUID().toString();
    String fileName         = randomId.concat(originalFileName.substring(originalFileName.lastIndexOf('.')));
    String filePath         = path + File.separator + fileName;

    File folder = new File(path);
    if (!folder.exists()) folder.mkdir();

    Files.copy(file.getInputStream(), Paths.get(filePath));
    return fileName;
}

The UUID prefix prevents filename collisions. The filename (not the full path) is stored in the Product.image column and served under /images/**.

10. Payment API

Payment is handled at the order-placement stage. The API is designed to be gateway-agnostic: the client (frontend or mobile app) communicates with a payment gateway (Stripe, Razorpay, etc.) directly, then sends the resulting transaction metadata to the backend for order finalization.

Endpoint

POST /api/order/users/payments/{paymentMethod}

The {paymentMethod} path variable (e.g., CARD, UPI, NET_BANKING) is stored on the Payment entity as a free-form string alongside the gateway-specific fields.

OrderRequestDTO (Request Body)

public class OrderRequestDTO {
    private Long   addressId;          // saved address to ship to
    private String paymentMethod;      // CARD, UPI, etc.
    private String pgName;             // gateway name: Stripe, Razorpay, PayPal
    private String pgPaymentId;        // gateway transaction/payment intent ID
    private String pgStatus;           // gateway status: SUCCESS, FAILED, PENDING
    private String pgResponseMessage;  // human-readable gateway message
}
